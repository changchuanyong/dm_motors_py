## 1. 反馈帧 ERR（`data[0]` 高四位）

它是**状态码**，不是故障位掩码：`0x00`/`0x01` 为使能状态，`0x08..0x0E` 为故障。

故障码出处（两处官方注释一致）：

```
damiao.h（C++例程）CAN_Receive_Frame 注释：
//     0xEE: communication error 此时格式段为错误码
//     8: 超压 9: 欠压 A: 过流 B: MOS过温 C: 电机线圈过温 D: 通讯丢失 E: 过载
```

- `SDK\电机SDK\C++例程\u2can\include\damiao.h:126-127`
- `SDK\电机控制例程\ROS1 例程\u2can\src\dm_hw\include\dm_hw\damiao.h:115-116`（同位置、同内容）

**实机验证（2026-09-23，DM-J6006-2EC @ COM5）**：失能时反馈码为 `0x00`；发出使能帧后收到
`data = 11 71 AA 7F F8 00 21 1E`，`data[0]` 高四位为 `0x1` → 使能后为 `0x01`，与「`0x00` 已失能 /
`0x01` 已使能」一致（该帧已成为 `tests/` 里的回归用例）。当前 SDK 的 `enable()` 按该实机记录
明确要求使能状态为 `0x01`；`0x00` 不会因为相对旧缓存发生变化而被学习成使能成功。
这是本项目的适用条件；更换采用其他状态编码的固件时需先验证语义。
说明书 PDF 原文建议人工再核对一次（本机缺 poppler 无法渲染）。

## 2. 报文分发：完整电机 ID 与待处理请求匹配

官方 SocketCan 例程 `damiao.cpp:678-695`：

```cpp
if(read_write_save==true&& motors.find(canID) != motors.end())
{//这是发送保存参数或者写参数或者读参数返回的数据
    if(frame.data[2]==0x33 || frame.data[2]==0x55 || frame.data[2]==0xAA)
    {   if(frame.data[2]==0x33 || frame.data[2]==0x55) receive_param(&frame.data[0]);
        read_write_save=false;   // 0xAA（保存应答）只清标志，不解析
    }
}
else
{/* 这是正常返回的位置速度力矩数据 */}
```

要点：

- 参数类应答的判别字节是 **`{0x33, 0x55, 0xAA}`**（读 / 写 / 保存），由「最近发过参数类命令」标志门禁。
- 官方 C++ SDK 也分两条路径（`receive()` 反馈 / `receive_param()` 参数），但**反馈路径同样不校验
  `data[2]`**——即官方两个语言实现都没有完全堵住"参数应答被当成反馈"的洞。本项目在 `recv()` 里补上了
  这个判别，属于对官方方向的补齐。
- **判别条件（本项目）**：`data[2] ∈ {0x33,0x55,0xAA}`，且 `data[0..1]` 组成的完整 Slave ID
  必须属于已注册电机。`motors_map` 同时包含 Master ID，因此查到对象后还要核对其 `SlaveID`。
  对本项目支持的 Slave ID `0..15`，使能/故障状态高四位不会再被错误地当作电机 ID。
- **归属判定**：参数候选帧的 CAN ID 必须对应该电机（Master ID、Slave ID，或 SDK 兼容的
  `0` / `0x7FF` 返回路径），并匹配待处理请求的 Slave ID、操作码、RID 和截止时间，才解析参数。
  不匹配或迟到时丢弃并计数，永不回退为状态反馈；此规则覆盖全部 RID，包括 50..55、80/81。
  请求最长等待 1 s，读应答不能完成写请求，保存应答只完成保存请求。
- **歧义处理**：失能反馈在个别位置/速度下可与参数应答逐字节相同，协议没有额外类型位。
  此时保守按参数类处理，不更新反馈计数或时间戳。若没有其他可确认的状态帧，SDK 刷新或使能失败。
  这是协议歧义的保守处理，不代表可以无条件区分全部报文。
- **为什么不能只按 `data[2]` 判别**（实机教训）：`data[2]` 是位置编码的低字节，**电机静止时它固定不变**。
  2026-09-23 测试中电机停在 `q_uint = 0x71AA`，其反馈帧 `data = 11 71 AA 7F F8 00 21 1E` 的
  `data[2]` 恒为 `0xAA` —— 只按单字节判别会让该电机的反馈被**持续**丢弃（refresh 帧与使能帧全丢），
  使能门禁因此误报。当前按完整 Slave ID 识别，该帧正常解析。
  原先增加 `data[3] ≤ 36` 的办法也已移除：它会吞掉负速度下的正常或故障帧，且漏掉高 RID。
  `tests/test_transport_regressions.py` 覆盖标记字节碰撞、故障状态和全部已声明 RID 的迟到应答。
- `receive_param()` 的字段解析：`slaveID = (data[1]<<8)|data[0]`、`RID = data[3]`、值在 `data[4..7]`，
  与本项目 `__process_set_param_packet()` 一致。

## 3. 编解码量程：用电机实际值，而不是固定表

官方 C 驱动 `dm_motor_drv.c`：

```c
motor->para.pos = uint_to_float(motor->para.p_int, -motor->tmp.PMAX, motor->tmp.PMAX, 16);
motor->para.vel = uint_to_float(motor->para.v_int, -motor->tmp.VMAX, motor->tmp.VMAX, 12);
motor->para.tor = uint_to_float(motor->para.t_int, -motor->tmp.TMAX, motor->tmp.TMAX, 12); // (-18.0,18.0)
```

`motor->tmp.PMAX/VMAX/TMAX` 初值为默认（`dm_motor_ctrl.c:39` 的 `motor[Motor1].tmp.PMAX = 12.5f;`），
随后由 `receive_motor_data()` 按 RID 21/22/23 读取覆盖（`case RID_PMAX / RID_VMAX / RID_TMAX`）。
因此启动时读取实际值并对齐编解码量程与官方做法一致；本项目用 `sync_motor_limits(motor)`
读取 PMAX/VMAX/TMAX，再通过 `change_limit_param()` 对齐 `MotorControl.Limit_Param`。
不读不齐时，只要电机实际量程与表不同，下发目标与回读反馈都会按比例偏。

## 4. 反馈时间戳与帧间隔

官方 SocketCan 例程每收到一帧就 `m->updateTimeInterval()`（记录 `stamp` 并计算间隔）。本项目用
`Motor.feedback_count` / `last_feedback_at` 做同样的事，并据此检测反馈超时。

## 5. 适配器帧的 CMD 字段

```
0x00: 心跳        0x11: receive success    0x01: receive fail
0x02: send fail   0x12: send success       0x03: set baudrate fail
0x13: set baudrate success                 0xEE: communication error（此时格式段为错误码）
```

官方 Python SDK 只处理 `CMD == 0x11`，其余全部静默忽略；本项目改为计数（`ignored_frames`），
用于区分"电机不回帧"与"总线出错/发送失败"。

## 6. 清错命令 `0xFB`（官方有、Python SDK 没有）

`dm_motor_drv.c:285`：

```c
void clear_err(hcan_t* hcan, uint16_t motor_id, uint16_t mode_id)
{
    uint8_t data[8];
    uint16_t id = motor_id + mode_id;          // 与 enable_old 的模式偏移规则一致
    for (int i = 0; i < 7; i++) data[i] = 0xFF;
    data[7] = 0xFB;
    fdcanx_send_data(hcan, id, data, 8);
}
```

Python SDK 没有对应函数，固件闩锁故障后无法通过 SDK 清错（后续项，本轮未实现）。

## 7. 本项目对官方 `DM_CAN.py` 的差异清单

保留官方函数名，对接收分发、缓存和控制检查做以下修改：

| 位置 | 改动 |
|---|---|
| 模块常量 | `PARAM_REPLY_MARKERS = (0x33, 0x55, 0xAA)`、`PARAM_REPLY_TIMEOUT = 1.0` |
| `Motor` | 记录 `feedback_count`、`last_feedback_at`、实测 `limits` 及 `status_name`；`NowControlMode` 初始未确认，`isEnable` 仅在使能流程成功后设置 |
| `MotorControl.__init__` | `_param_request`、`dropped_param_replies`、`ignored_frames`、可选 `feedback_timeout`；复制实例独立的 `Limit_Param`，发送缓冲仍为类级共享 |
| `addMotor()` | 校验 Slave ID/ Master ID 和重复映射，拒绝相互覆盖 |
| `sync_motor_limits()` | 读取实测 PMAX/VMAX/TMAX 并对齐编解码表；同型号量程冲突时拒绝继续 |
| `enable()` / `enable_old()` / `refresh_status()` / `check_status()` | 确认新反馈、明确的使能状态和反馈时间；使能失败尝试失能，状态异常会报错 |
| `switchControlMode()` | 先消费旧帧并清理目标缓存，确认本次应答后才登记已确认模式 |
| `change_motor_param()` / `change_limit_param()` | 尝试写量程参数时使该电机 `limits` 失效；改动编码表时使该型号已有 `limits` 失效，须重新同步 |
| 各控制接口 | 发送前检查本机状态、模式、量程和参数，发送后再次收取并检查本机反馈 |
| `recv()` | 按完整 Slave ID、CAN ID 和请求归属分发，所有 RID 的迟到参数候选帧均丢弃，不污染反馈；非 `0x11` 帧计数忽略 |
| `recv_set_param_data()` | 改为 `recv()` 的薄封装（原先只解析参数帧、且会丢掉未拆完的缓存） |
| `__read_RID_param` / `__write_motor_param` / `save_motor_param` | 发送时登记 Slave ID、RID、命令字和截止时间（保存命令 `rid=None`） |
| `read_motor_param()` / `change_motor_param()` | 先消费旧帧、清目标缓存；读取取消循环内早退，重试窗口耗尽才返回 `None` |
| `__extract_packets()` | 丢弃已扫描的无效前缀，只保留不足 16 字节的尾部，避免连续噪声导致缓存增长 |

**行为变化**（升级需知）：

1. `recv_set_param_data()` 现在也会解析反馈帧、并续用 `data_save` 缓存。
2. 无主或已过期的参数类应答不再被解析，直接丢弃并计入 `dropped_param_replies`。
3. 参数候选帧不会因保护窗口到期或 RID 大于 36 而被当作反馈；已使能和故障帧不会因速度字节
   命中 RID 范围而被丢弃。字节完全重合的失能帧按第 2 节的歧义规则处理。
4. SDK 的 `refresh_status()` 每次均要求所有已注册电机有新反馈；`enable(motor)` 先查询新状态，
   再确认本次使能后的新 `0x01` 反馈，`enable_old()` 也要求本次新反馈。使能失败会尝试失能；
   非 `0x01` 反馈或 `disable()` 清除 `isEnable`，单个 `0x01` 回包不能自动恢复控制资格。
   多台电机依次启动后需统一刷新，避免首台反馈过期。
5. 控制前必须注册电机、同步实际量程、成功切换模式并确认使能。参数无效或模式不匹配会报错，
   位置目标超过实测 `±PMAX` 直接拒绝；MIT 速度及力矩仍保留官方编码的饱和行为。
6. 控制接口检查本机；`check_status()` 可显式检查所有电机。检查失败抛异常，应用程序负责在
   `finally` 中逐台尝试失能并关闭串口。单次发送后的检查不保证已收到这次命令对应的新反馈。
7. 尝试写 PMAX/VMAX/TMAX 后，无论写入是否确认成功，都必须重新同步量程；公开修改编码表后，
   受影响型号已有量程记录也会失效。量程表按控制器独立复制，不代表 SDK 已支持多线程通信。

**管理层移除（2026-09-26）**：删除 `motor/motor_manager.py`，不再导出 `MotorManager`、
`MotorConfig`、四种指令参数类、`RunConfig`、`SineMotion` 或工厂函数。反馈记录、量程同步、
使能确认及指令检查进入 `Motor` / `MotorControl`；串口创建、目标计算、控制循环和退出清理
直接写在示例中。参数保存由调用方显式执行 `save_motor_param()`，示例的 `SAVE_PARAMETERS`
默认关闭。删除只服务旧封装的测试，保留协议解析、SDK 检查及示例清理的无硬件回归测试。

这里的重组沿用上文已有实机证据，并不新增实机验证记录；无硬件测试不能证明当前硬件运行结果。

更新官方 SDK 时的做法：重新 diff `damiao\SDK\电机SDK\Python例程\u2can\DM_CAN.py`，把上表逐条重新应用。
